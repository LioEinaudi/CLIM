# CLIM v0.3.0-alpha.1 — Developer Alpha / Preview

This is an opt-in developer preview for supported Codex workflows. It is not a
stable release or a production safety certification.

CLIM Shadow compares supported tool proposals with observed changes in a bounded
file sample. The new terminal card groups Pre/Post windows, highlights important
changes, and discloses unknown authority, coverage gaps and collapsed windows.
Its priorities guide human review; they are not security severity scores.

## Try the preview

```bash
git clone --branch v0.3.0-alpha.1 https://github.com/LioEinaudi/CLIM.git
cd CLIM
python -m pip install -e .
clim init codex --project /path/to/your/project
```

Open Codex in the target project, inspect and trust the installed definitions
with `/hooks`, and complete a coding task before generating a report:

```bash
clim report --project /path/to/your/project --format card --limit 20
clim report --project /path/to/your/project --format json --advanced
```

The Python package version is `0.3.0a1`. JSON remains the default output; card is
opt-in. `clim reconcile` retains its pending/incident acknowledgement semantics.

## Observation and limitations

- **Shadow does not intentionally block tool calls.** It is not an enforcement
  boundary. Guarded/Ask remain experimental, and the native sandbox/permission
  system still matters.
- **Live notices are OFF by default.** `clim notices on --project ...` enables
  experimental, nonblocking notices for explicitly proposed protected
  `apply_patch` targets. Target sets are deduplicated, with at most eight notices
  per session. Native TUI visibility has been checked; headless JSON delivery is
  not guaranteed. `clim notices off --project ...` disables them.
- **Task authority may be UNKNOWN.** Protected-path patterns and the Agent's own
  proposal do not establish authorization. Only independently registered host
  scope can support an authorization residual.
- **Shell coverage is incomplete.** Shell file-write semantics are not fully
  parsed. Inventory normally covers at most 250 paths and 4 MiB per file.
  Missing/unmatched Post, symlinks, unreadable or oversized files, and sampled-out
  paths remain UNKNOWN rather than retrospective success claims.
- **Attribution remains uncertain.** Other processes can write during a Hook
  window. An observed change does not identify a unique author or establish code
  correctness. Dirty baselines include staged, unstaged and untracked paths, but
  session-first line hashes are bounded preservation heuristics.
- **Protection templates are limited.** `.git/**` as a policy pattern does not
  imply that skipped Git internals are inventoried. Lockfiles and CI workflows
  are not explicit default protection categories; operators may add patterns.
- **Metadata can be sensitive.** Logs are local and persist until explicit purge.
  Same-user files are not tamper-proof. This release uploads no private native
  sessions, raw Hook inputs or local experiment archives.

The 11 internal `operator_review` forms are still incomplete. Alert precision and
reviewer-time savings have not been quantified. Controlled test effects are not
evidence of spontaneous Agent misconduct. No efficiency percentage, complete
coverage or production safety claim follows from the acceptance experiments.

Native acceptance covers Codex. Maintainer PR Preflight and Claude Code native
adaptation are outside this release.

## Feedback

Please try the preview on a disposable or version-controlled project and use the
[redacted operator-review template](https://github.com/LioEinaudi/CLIM/issues/new?template=operator_review.md).
We especially want feedback on card readability, distracting alerts, whether
important changes stand out, clarity of coverage gaps, and installation friction.

Do not post raw agent transcripts, Hook input, complete CLIM state, secrets,
private paths or proprietary code. Redacted excerpts and verified observations
are sufficient.

See [Known Limitations](https://github.com/LioEinaudi/CLIM/blob/v0.3.0-alpha.1/docs/KNOWN_LIMITATIONS.md). The final verified commit and
main CI receipt are appended by the publisher; the tag points to that commit.
